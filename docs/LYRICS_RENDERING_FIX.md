# 歌词着色与换句修复

日期：2026-10-13。代码已修复，八项本地 CTest 通过，新版已在本机运行；实际歌曲的听感同步仍待用户确认。

## 原因与修改

普通 LRC 的时间进度由 LyricsTimeline 正确计算，但 Direct2DRenderer 将高亮宽度初始化为整句宽度，仅逐字歌词分支会重新计算。因此普通 LRC 在起点就全句着色。现改为按句内进度计算高亮宽度；逐字歌词仍按音节时间戳与 DirectWrite 文本位置绘制。普通 LRC 没有逐字时间数据，渐进着色是整句区间内的估算。

旧换句动画在新时间戳到达后才开始 400 毫秒的滑入／淡入，新句首帧透明且移到可见区域下方，造成视觉上的歌词偏晚。现将过渡安排在下一句起点前最多 180 毫秒：旧句向上滑动并淡出，新句以未着色状态从下方进入；到起点已经在正常位置，才开始按自己的时间戳渐进着色。快速换句时，过渡长度不超过两句起点间隔的一半。长句横向滚动继续平滑，并根据滚动目标判断是否需要继续绘帧。

间奏保留逻辑维持：空白标记结束演唱区间，但不会清掉上一句；完成的上一句保持显示，到下一句非空歌词临近才进入过渡。动画进度直接由播放位置决定，暂停时冻结，拖动进度或切歌时直接对齐正确画面，不对已跳过的句子播放补间。下一句布局预先缓存，切换时复用。

前奏期间预览第一条非空歌词，保持未着色、未滚动；显示层选择首句，不改变演唱时间轴，首句仍按原始时间戳开始变蓝。拖回前奏也恢复首句的未唱状态。GPU 回归验证首句从前奏到起点的像素稳定，普通 LRC 与逐字歌词都不会提前着色。

本次保留 [LYRICS_TIMING_FIX.md](../LYRICS_TIMING_FIX.md) 中另一 AI 的曲长匹配、来源回退与缓存修改，没有用统一提前量掩盖歌词文件或播放位置的差异。

- 扩充 LyricsParserTests，覆盖普通 LRC 起点、四分之一／一半／四分之三进度、间奏结束、下一句起点和新句中段。
- LyricScrollTests 新增长间奏、空白标记、下一句起点、拖动回退以及 100 毫秒快速换句的过渡规则测试。
- Direct2DRendererTests 通过正常 GPU 绘制路径，并在开发测试进程中读回歌词像素；覆盖渐进着色、间奏保持、旧句高亮像素向上移动并减少、暂停过渡冻结、下一句起点与稳定帧一致、回退进度及逐字歌词。正式程序不执行 CPU 像素读回。
